# Retrieval and Evaluation Design

The current retrieval baseline is BM25-style lexical search. It tokenizes the question and document chunks, calculates a relevance score from term frequency and inverse document frequency, and returns the highest-scoring passages. This design is lightweight and reproducible, but it does not create semantic embeddings and it does not use a vector database. Questions that use synonyms or a different vocabulary from the documents may therefore retrieve weak evidence or no evidence.

Text is divided into overlapping word windows before retrieval. The baseline configuration uses a chunk size of 180 words and an overlap of 35 words. The comparison configuration uses a chunk size of 100 words and an overlap of 20 words. Smaller chunks can make evidence more focused, but they can also separate facts that belong together. Larger chunks preserve more context, but may contain unrelated material and can make a source less precise.

The evaluation script reads fixed JSONL question sets. Each line is one JSON object with an id, question, type, answerable flag, evidence list, and expected answer. For an answerable question, each evidence item names a source file and includes an exact quote expected to occur in a retrieved chunk. Unanswerable questions have answerable set to false and an empty evidence list. Those questions are excluded from retrieval recall because there is no expected supporting passage to retrieve.

Recall at k is the proportion of answerable questions for which at least one expected source-and-quote pair appears in the first k retrieved chunks. The project reports Recall@1, Recall@3, Recall@5, and Recall@10 overall and by question type. This is a retrieval metric, not a measure of whether a generated answer is correct, complete, or well written. Generated answers need a separate manual review with the labels correct, partial, wrong, or unsupported.

A no-context test asks the language model the same questions without supplying retrieved documents. Questions the model can already answer reliably provide weaker evidence of retrieval value, so they should be flagged and either replaced or explicitly discussed. Question sets should remain fixed between configuration comparisons; new questions can be added as separate entries, but existing questions should not be silently edited after results are inspected.
